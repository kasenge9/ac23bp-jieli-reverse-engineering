## Experiment 01 — Bluetooth Identification

### Objective

Determine how the module identifies itself to a host device.

### Equipment

- Windows computer with Bluetooth
- AC23BP module

### Procedure

1. Power on the module.
2. Open Bluetooth settings on Windows.
3. Search for available Bluetooth devices.
4. Observe the device name and MAC address.

### Observation

The device appears as:

```
CHARGE MINI
MAC: 93:91:63:79:F6:A9
```

### Result

The Bluetooth device can be detected and paired with a computer.

### Conclusion

Bluetooth functionality is operational and the device broadcasts a specific identity.

### Status

**CONFIRMED**

## Experiment 02 — Windows Name Cache Behavior

### Objective

Determine whether changing the Windows Bluetooth cache changes the actual Bluetooth identity.

### Equipment

- Windows computer
- Registry editor
- AC23BP module (powered on)

### Procedure

1. Locate the registry path: `HKLM:\SYSTEM\CurrentControlSet\Services\BTHPORT\Parameters\Devices\93916379F6A9`
2. Find the "Name" value.
3. Record the original value.
4. Modify the value to a new name (e.g., "TEST_NAME").
5. Re-scan for Bluetooth devices.
6. Observe what the speaker advertises.

### Observation

- Windows registry shows the modified cached name.
- The physical speaker continues broadcasting its original name: `CHARGE MINI`.
- Bluetooth reconnection uses the original device name.

### Result

Modifying the Windows-side registry does NOT change what the device actually broadcasts.

### Conclusion

The device's Bluetooth identity is generated by device-side firmware or configuration, not by the host OS.

This is a critical insight: to change the actual device name, we must modify the device itself, not the Windows record.

### Status

**CONFIRMED**

### Implications

The Bluetooth name must be stored in:
- device firmware
- nonvolatile configuration memory
- EEPROM or Flash

Further investigation required to locate and verify.

## Experiment 03 — Crystal Identification

### Objective

Determine the clock source used by the main SoC.

### Equipment

- AC23BP module
- Magnifying glass or microscope
- Multimeter

### Procedure

1. Power off the module.
2. Inspect the area near the main IC.
3. Locate any crystal component.
4. Record the marking.
5. Measure the component dimensions.
6. (If safe) measure continuity from crystal to IC pins.

### Observation

A component marked `24.000` is located near the main IC.

Dimensions approximately: 3.2 mm × 2.5 mm (standard SMD crystal package).

### Result

A 24 MHz crystal is confirmed present on the board.

### Conclusion

The SoC likely uses a 24 MHz clock source.

This is consistent with Jieli Bluetooth audio SoC designs and supports the AC6965E hypothesis.

### Status

**CONFIRMED**

### Next Steps

Trace both crystal terminals to the IC.

Identify the exact SoC pins connected to the crystal.

Verify the clock circuit topology (series resistance, load capacitors, etc.).

## Experiment 04 — Power Supply Identification

### Objective

Identify the main power rails and voltage levels on the board.

### Equipment

- Multimeter
- AC23BP module (powered OFF initially)
- USB power adapter or battery

### Procedure

1. Power off the module.
2. Set multimeter to DC voltage mode.
3. Place one probe on a known ground point (e.g., black wire, metal tab).
4. Place the other probe on suspected VCC locations:
   - Main IC power pin
   - Amplifier power pin
   - Regulator output
5. Power on the module.
6. Record voltage readings.
7. Power off before disconnecting probes.

### Expected Results

| Point | Expected Voltage | Actual Voltage | Status |
|-------|------------------:|----------------:|--------|
| USB input | 5 V | | |
| Battery input | 3.7–4.2 V | | |
| SoC VCC | 1.8–3.3 V | | |
| Amplifier VCC | 3.3–5 V | | |
| Regulator output | 3.3 V | | |

### Safety

Never apply probes to an unknown pin without first identifying its function.

If voltages appear abnormal, power off immediately.

## Experiment 07 — Oscilloscope Audio Path Verification (Advanced)

### Objective

Capture the audio waveform at various points in the audio path to verify signal routing.

### Equipment

- Oscilloscope (1 MHz+ bandwidth minimum)
- AC23BP module
- Bluetooth audio source (smartphone, computer)
- Headphones

### Procedure

1. Power on the module.
2. Connect oscilloscope ground to module ground.
3. Set oscilloscope to AC coupling, 1 V/div.
4. Connect probe to:
   - Bluetooth input (if accessible)
   - DAC output
   - Amplifier input
   - Amplifier output (with caution)
5. Play audio via Bluetooth.
6. Capture waveforms.

### Safety

Amplifier outputs may be high-impedance bridge-tied-load configurations.

Use a 10:1 probe and isolate the oscilloscope from ground loops when measuring amplifier output.
